# Анализ существующих механизмов Cua Driver и Open Computer Use (Prior Art)

В соответствии с п. 3.1 ТЗ проведено исследование существующих механизмов автоматизации GUI, безопасности и аудита в upstream-проектах:
- **Cua Driver:** [trycua/cua](https://github.com/trycua/cua) (версия 0.34.0, macOS)
- **Open Computer Use:** [showlab/computer_use_ootb](https://github.com/showlab/computer_use_ootb) и эталонная реализация [Anthropic Computer Use Demo](https://github.com/anthropics/anthropic-quickstarts/tree/main/computer-use-demo).

---

### 1. Архитектурное сравнение с Open Computer Use

| Критерий | Open Computer Use / Anthropic Demo | Cua Driver 0.34.0 | Наш прокси (`agent-computer-use`) |
| :--- | :--- | :--- | :--- |
| **Среда выполнения** | Виртуальный X11/Xvfb дисплей внутри изолированного Linux-контейнера Docker. | Нативный macOS (Darwin arm64/x86_64) поверх Quartz WindowServer и Accessibility API (`AXUIElement`). | Нативный macOS (мост поверх `cua-driver mcp`). |
| **Способ взаимодействия** | Низкоуровневые координаты `(x, y)` через `xdotool` / `pyautogui`. Слепой поиск по пикселям. | Семантический таргетинг элементов (`element_token` из дерева AX) или координаты `(x, y)`. | Семантический таргетинг + кэш токенов + проверка владения окном (`TARGET_MISMATCH`). |
| **Изоляция и песочница** | Контейнерная (Docker cgroups / Linux namespaces). Безопасна для хоста, но агент «не видит» реальных macOS-приложений. | Отсутствует. Процесс драйвера имеет прямые системные права Accessibility и Screen Recording хоста. | **Политики безопасности (L7):** строгий Allowlist/Denylist по `CFBundleIdentifier`, лимиты сессии, мгновенный kill-switch. |
| **Контекст процесса** | Отсутствует (для X11 весь экран — одна матрица пикселей). | Частичный: возвращает `pid`, `window_id`, `app_name`, но не Bundle ID. | Полный: строгая резолюция Bundle ID через `/usr/bin/lsappinfo` без шелла, сопоставление `pid <-> window_id`. |
| **Аудит и логирование** | Снимки экрана в файловую систему контейнера. | Локальная зашифрованная история (`--experimental-history`). | Структурированный JSONL-журнал, аудит вызовов со строгим маскированием текста ввода (`logTypedText: false`). |

### 2. Встроенные механизмы Cua Driver (Upstream: `trycua/cua`)

#### 2.1. Авторизация агента (`--permission-mode`)
* **Режимы доступа:**
  * `standard` (по умолчанию) — обычный режим автоматизации без интерактивных подтверждений.
  * `bounded` — запуск с флагами `--capability-manifest <path>` и `--approve-capability-manifest`.
  * `unrestricted` — запуск с полным обходом ограничений (`--dangerously-bypass-approvals`).
* **Оценка `--permission-mode bounded` как защиты второго уровня:**
  * *Специфика флага:* Согласно `cua-driver --help`, флаг `--permission-mode` относится к категории `agent authorization (serve only)`. Он настраивается на уровне фонового демона (`serve`), а клиентский процесс `mcp` подключается к нему.
  * *Ограничения манифеста:* Встроенный манифест возможностей Cua является статическим файлом, фиксируемым при старте демона. Он ограничивает доступные имена инструментов MCP (например, запретить `press_key` или доступ к определенным URL Chromium), но **не поддерживает контекстную проверку приложений macOS по Bundle ID в реальном времени** (не умеет разрешать `pid` -> `CFBundleIdentifier` и блокировать фоновые окна).
  * *Применимость:* В конфигурации с постоянным демоном `cua-driver serve` включение `--permission-mode bounded` рекомендуется как полезный **второй эшелон защиты (defense-in-depth)** для ограничения экспортируемых драйвером примитивов, в то время как наш прокси `agent-computer-use` обеспечивает динамический гранулярный контроль уровня операционной системы (L7 Policy Enforcement).

#### 2.2. Задержка курсора и анимация (`agent cursor overlay`)
Исследование справки и бинарника Cua Driver 0.34.0 выявило источник задержек при выполнении кликов:
* Оверлей курсора включен по умолчанию (`agent cursor overlay`).
* Драйвер эмулирует физическое движение мыши агента со сглаживанием траектории (`--style signature_arc`), используя фиксированное время планирования `--glide-ms` со значением по умолчанию **1430 мс** (`1.43 секунды`), плюс время стабилизации UI.
* Для полного отключения анимации и оверлея предусмотрен флаг `--no-overlay` (настраивается на уровне демона `serve`).

### 3. Заключение

Встроенных возможностей Cua Driver и контейнерных подходов Open Computer Use недостаточно для безопасной нативной работы на macOS:
1. Docker-подход `open-computer-use` изолирует систему, но не применим для управления реальными приложениями рабочей станции macOS.
2. Cua Driver предоставляет мощные нативные примитивы Accessibility, но не имеет слоя политик безопасности приложений, аудита действий и аварийной остановки.
3. Прокси `agent-computer-use` решает обе задачи: сохраняет преимущества нативного управления macOS и защищает рабочую станцию строгими политиками и аудитом.
